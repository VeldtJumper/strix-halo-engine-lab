# Measured gains: the changelog of shipped defaults

[English](measured-gains.md) · [Español](measured-gains.es.md) · [Main README](../README.md)

Every optimization that ships on by default is listed here with what it does, its measured gain, its exactness
evidence and its off switch. The fast path is the default for every engine; `auto` applies the documented admission
guards, and exactness is relative to the named numerical identity. Gains are workload-specific and must not be added.
The per-build campaign tables (for example DeepSeek `69c6bdab` → `6a5604bf`, the Qwen exact-prefill sweep, the GLM
prefill generations) stay on the model pages; the full item lists with preconditions, notices and evidence are in the
[optimization catalog](optimizations.md) ([machine-readable catalog](optimizations.json)); the master
baselines and inspection commands are in [methodology](methodology.md#defaults-and-off-switches).

## Shipped changes beyond the historical campaigns

The detailed campaigns on the model pages retain their measured build identities. Main also ships the following
changes; these measurements do not form a new combined performance sweep:

| Shipped default | Published measurement and scope | Evidence |
|---|---|---|
| Qwen HTTP automatic tiled prefill | T8192 vs explicit T2048: cold 17K TTFT 21.95 vs 22.93 s; two 8.5K prompts 11.08/11.11 vs 11.53/11.58 s. Same binary, interleaved arms, identical IDs. Memory tradeoff: 29 vs 55 slots in this configuration. | [Serving prefill](optimizations.md#qwen-serve-prefill) |
| Qwen MoE XOR rows | Routed-call time −2.6% to −8.2% at 3072–4864 rows on real layers, ABBA; no change at T8192. Default only for admitted automatic CLI shapes. | [XOR rows](optimizations.md#qwen-moe-xor-rows) |
| Qwen vector merge+commit | 3.81 vs 3.99 ms per admitted T8192 merge call; about −0.02 s at 32K. Byte-equal fixture outputs and equal 4K/32K generated tokens. | [Vector merge](optimizations.md#vector-moe-mergecommit-in-tiled-prefill) |
| DeepSeek prepared expert discovery | Fresh-process ABBA ×2: whole-run wall mean 66.0 → 43.8 s; includes a cold page-cache visit in the original-loader arm. R1 position records equal on both ranks. This is loading, not decode throughput. | [Prepared loading](optimizations.md#ds-prepared-load) |
| DeepSeek bounded agent prefix retention | Cached 2K prefix in an 8K prompt: −3.63 s (−24%) mean; fresh-process ABBA ×2, identical text and IDs. | [Prefix qualification](engine/serving/ds41-prefix-cache-qualification.md) |
| DeepSeek F16 Engram projection prefetch | Isolated 1024-row projection 88.1 → 75.8 ms; aligned F16 views only, byte-equal output. End-to-end TTFT not separately measured. | [Engram prefetch](optimizations.md#engram-prefill-projection-tile-with-prefetch) |
| DeepSeek attention LDS swizzle | R6 decode −0.20%, R1 neutral; N8 median −0.04%. Both-rank exact gates; no broad throughput gain claimed. | [Pair operator defaults](models/deepseek-v4.1/production-defaults.md) |
| RTX write-back stream / copy-engine pacing | Stream: DSpark plain/controller per-commit time −2.0%/−6.4% over four alternating loads, identical chat tokens. Pacing: bracketed comparison within noise. | [Stream](optimizations.md#write-back-stream), [pacing](optimizations.md#rtx-ce-pacing) |
| MiniMax DSpark serving auto | Same-load, per-request qualification: JSON −34.6%, code −17.5% wall time; tested prose stays plain and is not slower; identical IDs in every class. | [Automatic admission](optimizations.md#dspark-automatic-admission) |
| MiniMax MSA mode 5 | Mode 5 vs 3: 8K/1K TTFT −0.129/−0.109 s, n=6 each; intervals include zero. Both-rank tokens/state/final-row digests identical. | [MSA mode 5](optimizations.md#msa-prefill-mode-5) |
| MiniMax prefill gather and q/k/v | Fresh process per arm, 4 interleaved A/B runs: 8K TTFT −2.3 to −4.3 %, 32K −4.3 to −5.3 %. Both-rank tokens/state/final-row digests identical; operator outputs byte-identical. | [Token-major gather](optimizations.md#prefill-moe-token-major-gather), [q/k/v on the v4 core](optimizations.md#prefill-qkv-projections-on-the-v4-core) |
| RTX multi-disk expert streaming | Exact prefill service, one/two/one drive: 8K 13.27/13.12 → 10.64 s; 32K 19.39/18.98 → 17.44 s. State hash, logits and next token equal. Decode throughput was not measured. | [Two-drive measurements](models/deepseek-v4.1/rtx-two-drives.md#measurements) |

Qwen dense form-4 WMMA register-bank pinning also ships default-on: it keeps operand banks distinct
without changing instructions or values. Each build can be checked with
[`tools/check_wmma_banks.py`](../tools/check_wmma_banks.py); the
[catalog](optimizations.md#register-blocked-dense-projections) does not publish a complete-workload speed gain.

MiniMax serving measurements are paired runs, not a throughput improvement claim. C4 throughput was
28.1/29.2 vs 30.0/31.1 tok/s off; C8 31.5/32.7 vs 32.3/35.8. C8 worst decode gaps fell to
1.19/1.11 from 7.49/6.79 s. The gates compare complete IDs, committed state, all normalized prompt-row
digests and first/continuation logits on both ranks, plus parked parent/child state for nesting;
either rank's mismatch fails both. Reference choice depends on whole-prefill, FIFO or standalone-B1
execution. Draft-array coverage remains limited to the documented legacy route; extended
legacy/reorder coverage awaits GPU requalification. See
